# The Oath of Cinders / El juramento de ceniza

Two native HocusPocus dark-fantasy music films, authored in English and Spanish.
Open `/examples/ashes-oath/` in the running app to watch, download and inspect the
measured production times.

The collection remounts `dark-motion-knight-passage` with eight new illustrations,
three moving environments, two animated transparent characters, a kneeling pose,
a near thorn prop and a fixed shoreline ledge. Source media was generated by
MiniMax Image-01, YuE2 and H3 Fused through HocusPocus; interpolation and matting
also ran through the application's native tools. All shots were saved and
exported by Video 3D, then assembled with their music by Video Editor.

## Edit and reproduce

1. Open **Studios → Video 3D → Shot library**. The saved shot names begin with
   `The Oath of Cinders` or `El juramento de ceniza`.
2. Alternatively, extract `scenes.zip` and import an individual `.world3d.json`
   from Video 3D. These documents use the included `/examples/ashes-oath/assets/`
   media, so the same application installation can resolve every layer.
3. Edit characters, environment, foreground, camera or effects. **Effects →
   Animated trajectory** contains the measured-beat ember and rune keyframes.
4. Export the shot through Video 3D and assemble it in Video Editor. `plan-en.json`
   and `plan-es.json` preserve ordering, exact source-audio trims and scene clocks.

The English and Spanish performances have independent beat analyses. Cuts are
placed near musical phrases; small moving embers peak on detected beats and rune
seals expand on detected downbeats. Camera motion is restrained and has no roll.
Character motion stays at its natural source speed. This is not body-motion
retargeting or a generated dance performance.

The WAV files retain the full original takes. The final films trim the long
instrumental introductions. Optional SRT/VTT captions use the written lyrics and
native audio alignment; individual sung pronunciations can differ from that text.

## Measurements and remaining improvements

`production-report.json` records actual processing and queue times, native job
and task identifiers, and the elapsed production clock. `beat-audit-*.json`
records frame quantization relative to the detected source beats. Processing sums
are distinct from elapsed wall time and include machine stalls within jobs.

This production exposed an opaque-video readiness mismatch: `transparent: false`
was omitted during document parsing but was treated as a different media binding.
The accompanying code fix normalizes that flag when comparing bindings.

Useful follow-ups:

- A UI action to turn detected beats into editable effect trajectories; this
  collection already contains those trajectories as ordinary native scene data.
- Resumable chunked video matting and a fast preview mode. Refined per-frame
  matting was much slower than video generation, especially during disk stalls.
- A recover/retry control for a media-load timeout after a slow disk read.
- Soundtrack fade-in/fade-out controls in Video Editor.

No external renderer was used. Local clients transported native API requests,
authored scene documents, packaged results and performed read-only checks.
